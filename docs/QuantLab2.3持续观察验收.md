## 首次观察与历史可用性

- `collected_at_utc`：该数据字节第一次在本观察器得到成功 HTTP-200 响应的实际完成时间；重复确认另存 `last_confirmed_at_utc`，下载次数和确认次数分别记录。
- `first_observed_at_utc`：本观察器已提交日志中首次见到**相同源对象、相同 SHA-256**的时间。它不是全球首次观察，也不是本项目此前从未见过该数据；2.2 已保存过这些字节的更早采集记录，仍原样保留，不被新时间覆盖。
- `first_publisher_verified_at_utc`：观察器首次具备该 ZIP 和匹配官方校验文件的日志提交完成时间。这里的“verified”指校验值一致，不代表数字签名、官方发布时间认证或字段语义认证。
- `source_version_sha256`：原始 ZIP 内容版本；同一 URL 返回新字节形成修订，版本首次观察和历史版本都保留。A→B→A 不会把 A 的第一次观察改成最后回退时间。
- `published_at_utc`：始终 null。HTTP Date、Last-Modified、ETag 和本机时间不被解释为首次官方发布时间。
- `research_available_at_utc`：不早于事件窗口结束、所有支持包首次校验入账及既有语义核验时间。日志截止查询按**完整提交轮次**过滤，未完成轮次不提前暴露；快照冻结截止点，后续采集不改变旧快照。

本轮两个 metrics 版本在观察器中的首次成功完成时间分别是 10 月 23 日 **02:29:04.071703** 和 **02:29:10.496451 UTC**；首次完整校验入账是 **02:29:17.105045 UTC**。它们发生在对应市场事件之后，属于回补，不可注入 10 月 20/21 日当时的决策。

这只建立了本观察器的实际见证时间，尚无官方历史首次发布证明，也没有外部可信时钟公证。`verify` 核对现存日志链和对象；要校验某次固定的完整观察状态，应同时传入 `--output` 快照。仅靠本地现存链不能证明尾部从未被整体删除，保留 Git 中的快照锚有助于发现这一变化，也不声称阻止有权限的人连同全部历史重新编造。崩溃遗留且没有完整观察日志的字节只列为 orphan，不能据此估算更早的首次观察时间或准入。

## 增量、修订与字段隔离

每轮只请求未观察对象、到期的缺失对象，以及最近两日到期的复查对象；默认每轮最多 25 次请求。已取得对象默认 24 小时复查，404 默认一小时后可重试；未访问的新对象优先，历史补采可分轮推进。`--refresh` 可有界复核历史对象，仍受每轮上限约束。默认开始日期为新观察器启动前三个 UTC 日期，后续自动沿用已保存的起始日期。

原始响应存入 `objects/<SHA256>.bin`，同字节只存一份，200/304/404 的各次访问记录都不丢。每轮日志不可覆盖，包含前序指纹及配置指纹。单写者锁防止并发；临时文件完整写入并 fsync 后发布。进程硬退出后可能留下锁、临时文件或 orphan，应先确认没有活动写者再人工检查，不能自动把它们认作成功记录。

新文件或修订版即使通过官方校验，也不会自动继承 taker 语义白名单；必须匹配已有契约的 metrics 和所有参考包精确指纹。本轮未取得的 10 月 22 日不补零、不插值、不用相邻日期推断。旧数据和 2.2 的归档验证/标准化代码不改写。

**OI、OI 价值和三类多空比全部隔离**，这 576 行中的五个字段均未准入。独立时间证据缺口沿用 2.2 已记录的阻碍，本轮没有重试受限的 Tardis 许可页面，也没有通过 Binance 插件或 REST API 绕过限制。新增归档不会因为本观察器可下载就变成有资格的独立时间参考。

数据条款在每轮先确认且必须匹配已审阅版本；条款变化、403/451/429、网络错误、异常重定向或发布者校验失败均保留可取得的响应/本地错误证据并停止。后续自动轮次不会自动重试受限状态；只有来源恢复且完成审核后，操作者才可显式使用 `--resume-after-review`。该参数不修改源访问条件，也不是绕过限制的工具。

## 最小运行方式

不需要第三方依赖或 API 密钥，Python 3.10+：

```console
# 实际验收样本：完全离线校验和固定快照重放
python -m research.archive_observer verify --root data/archive_observation/binance_um_btcusdt_v1
python -m research.archive_observer verify --root data/archive_observation/binance_um_btcusdt_v1 --output data/archive_observation/binance_um_btcusdt_v1_snapshot

# 自己的独立观察根目录；请勿继续写入上面的 Git 固定验收样本
python -m research.archive_observer collect --root runtime/archive_observer_v1
python -m research.archive_observer watch --root runtime/archive_observer_v1 --interval-seconds 3600
python -m research.archive_observer snapshot --root runtime/archive_observer_v1 --output <新的独立快照目录>
```

`watch` 是前台循环，Ctrl+C 停止；不注册计划任务、不启动后台窗口、不修改现有自动任务。每轮遇限制退出，CLI 返回非零；正常 404 作为缺口保留而不伪装成功。旧文件超过最近复查范围后仍保留原证据，但不会声称持续监控所有历史文件的每次修订。

未来只有在真正积累连续观察、明确历史可见性且具备足够可信样本后，才能讨论接入已有固定统计协议。当前两次、约95 秒的归档观察远不是长期前瞻验证；没有训练、回测、账户动作或收益结论。
