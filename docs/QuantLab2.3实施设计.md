# Quant Lab 2.3：前瞻数据证据与持续采集设计

本阶段只建立独立观察证据，不改变策略、固定 Walk-forward 协议、纸面账户或任何现有自动任务，不连接私人账户或加入下单功能。

1. **来源与边界**：仅访问正常可用的官方 Vision BTCUSDT USDⓈ-M daily/metrics、5m K 线及对应 `.CHECKSUM`。每轮先核对数据条款；未知条款版本停止。403/451/429 等限制保留响应并停止，无代理、备用主机或自动重试。Binance 插件没有归档文件下载功能，不用受限行情 API 替代。
2. **存储事实**：独立根目录保存按 SHA-256 寻址的原始响应和不可覆盖的逐轮观察日志。日志按前序指纹串联；单写者锁及临时文件发布防止并发和半成品误入账。相同字节只存一份，但重复观察仍保存事件。离线验证不访问网络。
3. **增量与修订**：固定起始日期，逐轮纳入新增已结束 UTC 日期，重试未取得的归档并按间隔复查已取得对象。支持条件请求；304 只能引用同 URL 已有的完整字节。新指纹成为新版本，旧版本、失败响应和修订链全部保留，校验失败不得被当作成功采集。
4. **时间契约**：分别记录请求/响应完成、每一版本首次观察、首次官方校验成功、源标签和研究可用时间。首次观察只代表本观察器见到该字节，官方发布时间仍为未知。离线截止时点查询不得读取未来日志。刚下载的历史文件是回补；连续观察证据也不等于前瞻预测样本。
5. **字段准入**：保持 2.2 原代码和输出不变，复用已审计的精确 metrics/参考包指纹及各自偏移。新版本或缺少所需支持证据即隔离；不自动用一次相关性比较扩充白名单。OI、OI 价值和多空比因没有合格独立时间参考继续隔离，明确显示阻碍。
6. **最小接口**：`collect` 执行有界一轮；`watch` 在前台按间隔重复同一流程，遇限制停止；`verify` 重放日志并校验原始字节/官方校验/链；`snapshot` 输出截止时点的覆盖、缺口、修订、准入状态及证据清单。默认写入独立 runtime 目录；本轮发布一个有限的真实采集样本作为 CI 可重放验收证据。不安装或更改定时任务。
7. **验收与故障测试**：真实访问次数与合格归档数分别报告；列明覆盖、缺口、字段隔离、校验及实际观察时长。测试覆盖重复/增量、修订、404、403/451/429、网络故障、校验不一致、条件响应无先前字节、日志/对象损坏、并发锁、截止时点和旧版本契约隔离。运行全部现有测试和 Linux/Windows CI，通过独立 PR 交付。

证据的完整性由已保存字节和日志指纹支持，不声称本机时钟获得外部公证，也不把内容哈希视为官方数字签名。长期采集结果只能随真实时间推进而累积，首轮不足会如实报告。
