# 纸面观察器 V2 运行手册

## 运行与停止

Python 3.10+，只依赖标准库。在仓库根目录运行：

```console
python -m strategies.paper_trader
python -m strategies.paper_trader --loop
python -m strategies.paper_trader --status
python -m strategies.paper_trader --stop
```

一次运行会检查最新已收盘日线、处理尚未记账的执行日，并导出视图。首次启动只观察当前执行日；重启后按 checkpoint 补齐后续日期。行情不足以覆盖 checkpoint 时停止并记录错误，不能通过删除数据库来掩盖缺口。

`--loop` 在启动时立即检查。成功后等到下一个 UTC 00:10；失败后每 60 秒重试。`--stop` 写入停止标记，循环通常在一秒内退出。机器关机或睡眠时不会继续采集，恢复后会补跑并标注延迟。

## Windows 后台与登录自启

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File deployment/paper-service.ps1 -Action Start
powershell -NoProfile -ExecutionPolicy Bypass -File deployment/paper-service.ps1 -Action Status
powershell -NoProfile -ExecutionPolicy Bypass -File deployment/paper-service.ps1 -Action InstallTask
powershell -NoProfile -ExecutionPolicy Bypass -File deployment/paper-service.ps1 -Action Stop
```

可用 `-PythonExe` 指定解释器；默认先查找 Codex 提供的运行时，再使用 PATH 中的 Python。后台窗口隐藏，控制台输出保存在 `runtime/paper_v2/runner.stdout.log` 和 `runner.stderr.log`。登录任务名称为 `quant-lab-paper-observer`，使用当前用户的普通权限；`RemoveTask` 可移除。机器策略拒绝注册时需要管理员处理，该步骤不能算作已完成。

## 文件与记账

| 文件 | 用途 |
|---|---|
| `paper.sqlite3` | 唯一权威账本，状态、成交和每日权益在同一事务中提交 |
| `state.json` | 当前账户与成交模型的导出视图 |
| `health.json` | 最近检查结果、数据日期、下次检查时间；命令行状态会另外判断是否逾期 |
| `trades.csv` | 模型成交价、费用、信号日、执行日、观察时间与延迟 |
| `equity.csv` | 无成交日也保留权益；`final=0` 是当日暂定估值 |
| `snapshots/*.json` | 公开 OHLC 原始行、来源、采集时间、已收盘日期和 SHA-256 |

所有路径均位于 `runtime/paper_v2/`，不会随 Git 提交。JSON/CSV 导出失败时数据库仍保留已提交的交易；修复文件权限后再次运行，会重新导出，不能手工重复补单。

研究和观察器共用 `strategies/execution.py`。上一根收盘决定信号，下一根开盘加滑点决定模型成交价，双边扣费。停机补跑是历史模型重放，`delay_seconds` 表示开盘后多久才观察到；这些记录不等于真实市场成交。研究端的期末强制结算仅用于比较收益，持续纸面账户不强制平仓。

## 每日检查与复盘

1. 查看 `--status`：应为 `ok` 或 `recovered`，最新已收盘日应为 UTC 昨日。检查出错或逾期返回退出码 1。
2. 核对 `equity.csv` 当天记录、上一天 `final=1`；有成交时逐笔核对信号、开盘模型价、费用和延迟。
3. 查看数据库 `runs` 中的错误与恢复，保留原快照。没有金叉或死叉时零成交是正常结果。
4. 每周汇总实际采集日期数、自然退出交易数、费用、权益和错误次数。把补跑天数与当天实际观察分开，不把少量历史重放写成四周前瞻实测。

Hummingbot 是另一种基于实时订单簿的纸面撮合。其做市样例与这里的 MA 日线策略不同，不能拼接成同一条收益曲线。
