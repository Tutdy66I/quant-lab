# Quant Lab 2.2 第二阶段：归档标准化与独立数据验证

2026-10-22；基于 main `b818886b65f4a01858022ddc22a3d55d1b85609d`。

已实现独立离线适配器 `research/archive_normalizer.py`。它只读取第一阶段保留的本地原始文件，不访问网络、不请求账户权限，不导入策略或运行服务。输出仅为标准化记录、隔离记录、质量诊断和描述性统计；没有历史预测、选参、回测或纸面账户接入。

## 接纳范围

第一阶段经验验证的范围是 **BTCUSDT USDⓈ-M、2026-06-24/25、两个精确 ZIP 版本中的 `sum_taker_long_short_vol_ratio`**。源标签 T 表示 `[T,T+5min)` 的开始，事件时间保守记为窗口的排他结束 T+5min。时间语义契约 `semantic_contract.json` 记录精确 SHA-256、参考 K 线包、核验时间、字段及局限；相同日期而不同 ZIP 指纹也不自动接纳。

这是一份限定样本的经验契约，不是 Binance 对全部历史字段的官方保证。当前样本未复现 Issue #491 的切换主张，所以没有按日期硬编码时间平移。不能把两天结论推广到全部币种、历史日期或未来修订。

OI、OI 名义价值、账户多空比、持仓多空比、所有未验证日期/版本的 taker 比率，以及资金费率的全部字段，都保留在隔离输出中。资金费率 `calc_time` 不被冒充为已验证的事件时间。五分钟 K 线只作为交叉核对证据，不输出为模型价格特征。

“独立验证”指本适配器从原始 ZIP 重新计算、与另一类归档文件交叉核对，不信任第一阶段 `analysis.json` 的计算结果；参考数据仍来自 Binance，**不等于独立交易所来源或逐笔 aggTrades 重构**。

## 校验与标准化规则

1. 逐个核对全部 40 个来源响应的字节数和 SHA-256，拒绝越界路径、重复 receipt、采集时间倒置；数据及校验文件都要求成功的官方 Vision 来源记录。
2. 对 12 个 ZIP 再验证官方 `.CHECKSUM`、成员名、解压大小和精确 CSV 表头。schema 变化、缺少校验文件或必需参考包都不能降级为无校验接纳。
3. 保留原始文件和来源行号。按 `symbol,field,window_start` 排序；相同数值与相同时间契约的重复记录合并并保留全部来源，研究可用时间取较晚值。数值或窗口语义冲突时整组隔离，禁止 first/last-wins。
4. 检查每个 metrics 日文件的 288 点 UTC 五分钟网格：重复、逆序、无效标签、偏离网格、缺失标签逐项报告；不取整、补零、插值或前向填充。接纳范围另查标准化后的缺口，不把无资格字段的缺口混入合格数据统计。
5. 对每个已接纳版本重新用 K 线 `taker_buy_volume/(volume-taker_buy_volume)` 核对当前窗口与前一窗口。要求当前窗口 288 对、相关系数至少 0.99，且比前一窗口高至少 0.5；支持文件指纹也必须匹配契约。这个检查只验证窗口解释，不把非零误差掩盖为逐笔完全相等。
6. 输出使用 UTF-8/LF、固定 Decimal 精度及明确舍入规则。清单绑定源 receipts 指纹、适配器源码 LF 指纹和所有输出文件指纹；离线 verify 重建全部输出并逐字节比较，包括 manifest，不只是核对自报哈希。源码变化需要新版本输出，旧清单不会静默接受新算法。

## 四类时间与可见性屏障

| 字段 | 含义 |
|---|---|
| `source_label`、`window_start_utc/window_end_utc` | 原始标签及经验证的半开聚合窗口；不覆盖原标签 |
| `event_time_utc` | 聚合完成的排他结束时间，不是发布时间 |
| `published_at_utc` | 当前来源没有首次发布证据，一律 null；不采用 HTTP Date、Last-Modified 或调用者自填日期推断 |
| `collected_at_utc` | 对应原始 ZIP 的实际采集完成时间；校验文件、参考包及其校验文件的最晚采集时间另存 `evidence_collected_at_utc` |
| `semantic_verified_at_utc` | 此限定语义契约的核验时间，2026-10-22 08:54:57 UTC |
| `normalized_at_utc` | 此次派生数据的实际生成时间；离线重放使用清单所保存的同一时间，不伪造新采集 |
| `research_available_at_utc` | 事件结束、全部支持证据采集完成、实际标准化时间三者最大值；生成时间还必须不早于语义核验和所有输入采集 |

首版实际生成于 **2026-10-22 08:59:57.378200 UTC（香港 16:59:57.378200）**。因此这些六月的窗口最早只在这次生成后可用于本项目研究，绝不能注入六月当时的历史决策。隔离记录的事件时间和研究可用时间为 null，仅保存原始标签、采集时间和原因；它们不具备默认模型准入资格。

## 使用和复现

在仓库根目录运行，仅需 Python 3.10+ 标准库：

```console
python -m research.archive_normalizer verify --output data/archive_normalized/binance_um_btcusdt_v1
python -m research.archive_normalizer build --output <新的独立输出目录>
python -m unittest discover -s tests -v
```

`--source` 可指定相同 receipt 格式的本地证据目录，但不会因换目录而扩大语义白名单。`build` 拒绝覆盖已有目录，也拒绝输出到源证据目录内部或其祖先。无网络选项、API 密钥、订单参数或定时入口；不改现有自动任务。

`accepted.jsonl` 是唯一完成字段准入的输出。`quarantine.jsonl` 保存未确认或冲突的数据及原因，不能作为 accepted 的替代输入。`manifest.json`、`semantic_contract.json`、`quality.json`、`statistics.json` 和 `report.md` 构成完整可审计输出。原始 ZIP 保留在第一阶段目录，不复制、不覆盖；raw 文件完整性在每次 build/verify 时重新检查。

数据、衍生统计和本报告遵循 Binance Vision 的 CC BY-NC-SA 4.0 及第一阶段保存的来源条款；来源署名见输出 manifest 和第一阶段 `LICENSE.md`。本阶段无新增采集，也没有经插件或其他主机绕过现有 HTTP 451 限制。

本地最终 **96/96 测试通过**：原有 84 项及新增 12 项。新增离线测试涵盖字段隔离、四类时间屏障、已校验修订仍隔离、损坏原始字节/发布者校验、缺失参考、越界/重复 receipt、乱序/重复/缺口、输出不可覆盖、字节重放及数值异常。中间一次完整运行出现原有纸面并发测试的 Windows 临时文件 `WinError 5`，最终全套复跑通过，未改该测试或纸面实现。跨平台 CI 状态见本 PR checks。
